## Integration Tips

- **ReadMe / Mintlify**: Use their built-in analytics (page views, search queries, API explorer usage) as primary signal sources for the Documentation Signal Report. Both support custom analytics events to track "Try It" button clicks and copy-paste events.
- **Segment / PostHog**: Fire a `docs_page_viewed`, `quickstart_completed`, and `first_api_call` event from your docs site to join docs behavior data with signup and activation data in your data warehouse.
- **Intercom / Customer.io**: Use Intercom's Articles to serve contextual docs within your product dashboard. Connect API call behavior to trigger the activation email sequences in Customer.io with zero manual effort.
- **GitHub**: Set up a `docs` label on your GitHub repo Issues. Configure a Zapier workflow that creates a Linear/Jira ticket for every Issue with the `docs` label, auto-assigned to your DX team with the Documentation Debt score calculated.
- **Google Search Console + Ahrefs**: Connect Search Console to surface actual search queries landing on your docs. Use Ahrefs to identify competitor docs pages ranking for keywords you should own. Run a monthly "docs keyword gap" analysis to prioritize new pages.
- **Algolia DocSearch**: Install Algolia DocSearch (free for open-source/documentation sites) to power docs search and capture zero-result queries automatically in Algolia's analytics dashboard — the single highest-ROI data source for finding content gaps.
- **Notion / Linear**: Build your Documentation Debt Backlog in Linear (for engineering-adjacent teams) or Notion (for content-heavy teams). Use the Priority Score formula to auto-sort the backlog weekly.

## Troubleshooting

**Problem: TTFC isn't improving despite rewriting quickstarts.**
Solution: The bottleneck is rarely the content itself — it's usually friction in authentication (API key scoping), environment setup (dependency conflicts), or a missing prerequisite (e.g., needing a webhook URL). Instrument your quickstart with specific analytics events at each step (`quickstart_step_1_completed`, `quickstart_step_2_completed`, etc.) to identify exactly where developers drop off. Then fix that specific step, not the entire quickstart.

**Problem: Docs traffic is high but signup conversion from docs is < 1%.**
Solution: Docs traffic often has very low commercial intent — developers are researching, not buying.
