## Troubleshooting

**Problem: Developers try the AI feature once, see a mediocre output, and never return**
- *Root cause:* The first AI output experience is undifferentiated — the developer used a generic input and got a generic output. They didn't know how to prompt for quality.
- *Fix:* Redesign the AI feature's first-use experience to be guided: pre-fill the input with a realistic example from their industry, show the output before asking them to enter their own data, include a "improve this output" tutorial right in the first-use moment. In documentation, lead with the highest-quality output example, then explain the prompting technique that produced it. The first impression of an AI feature is everything.

**Problem: Compliance content hub exists but enterprise deals still stall at security review**
- *Root cause:* The compliance documentation is written for general audiences, not for the specific compliance framework the enterprise buyer operates under (HIPAA, FedRAMP, PCI-DSS). Security reviewers need answers to their exact questions, not general AI safety statements.
- *Fix:* Conduct 5 exit interviews with deals that stalled at security review. Collect the exact questions the security team asked. Build compliance FAQ entries that answer each question verbatim. Offer a "live security review call" with your security team for enterprise prospects — this converts at 4x the rate of documentation alone and surfaces new objections to document.

**Problem: Benchmark reports are dismissed by skeptical developers as marketing content**
- *Root cause:* The benchmark methodology is not reproducible. The developer cannot run the test themselves to validate the results. Unverifiable benchmarks trigger the "too good to be true" response in technical audiences.
- *Fix:* Publish the full test dataset (anonymized if needed) on GitHub. Publish the evaluation code. Invite community members to run the benchmark and submit their results. Create a "community benchmark" section of the report where others have independently reproduced results. Technical credibility comes from reproducibility, not from polished report design.
