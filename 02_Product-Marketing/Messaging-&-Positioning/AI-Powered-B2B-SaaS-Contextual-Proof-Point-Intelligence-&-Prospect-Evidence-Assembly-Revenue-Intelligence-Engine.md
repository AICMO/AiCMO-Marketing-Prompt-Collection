## Integration Tips
- **Salesforce / HubSpot CRM:** Create a custom "Proof Package" object linked to the Opportunity record. Trigger this prompt via a Zapier/n8n automation when a deal moves to Stage 3+ — auto-populate a CRM note with the generated package, tagging the Account Industry and Deal Size for searchability.
- **Seismic / Highspot / Showpad:** Tag all proof assets in your sales enablement platform with structured metadata (Industry, Company Size Tier, Buyer Role, Pain Category, Competitor Displaced). Feed this metadata as the "PROOF ASSET LIBRARY" input — the AI agent queries tags rather than requiring manual input.
- **Gong / Chorus:** Use call transcript summaries as input for the "Stated Pain Points" and "Objection History" fields. Automate a post-call workflow: Gong transcript → extract pain/objections via LLM → trigger proof package generation → push to rep's Slack or CRM note within 30 minutes of call end.
- **Notion / Confluence Proof Library:** Build a structured database of proof assets with fields for Industry, ARR Range, Role, Pain Category, Outcome Metric, Competitor Displaced, and Date Published. Use the database as a live reference library — the AI selects from current entries and flags outdated ones (>18 months old).
- **Clari / Boomerang / Outreach:** Embed proof package recommendations in deal signals — when Clari flags a deal as "at risk," auto-trigger a proof reassembly to see if stronger evidence exists. Push recommended proof to rep's next email sequence as personalized content blocks.
- **Slack Workflow:** Build a `/proofpackage` Slack command that accepts a CRM opportunity ID, pulls deal context, runs this prompt, and returns a formatted Slack message with the top 3 proof points + evidence narrative — ready for the rep to copy into their next email or meeting prep doc.

## Troubleshooting

**Problem: The AI selects proof points that don't feel specific enough — outputs feel generic.**
*Solution:* The quality of the "PROOF ASSET LIBRARY" input is the primary driver of output specificity. Instead of listing case study titles, paste the actual quantified outcomes (e.g., "FinTech firm, 600 employees, reduced churn by 22%, saved $1.4M annually in CS costs"). If your library is thin, instruct the AI to "generate representative examples based on our ICP and category, flagging them as [REPRESENTATIVE]" — then validate with your customer success team before using in deals.

**Problem: Proof gaps module identifies too many gaps — feels overwhelming.**
*Solution:* Add a prioritization instruction: "Rank proof gaps by deal-stage impact only — flag gaps that will likely block THIS deal from closing, not gaps for general library improvement." Then build a separate quarterly process for systematic proof gap closure rather than trying to bridge all gaps per-deal.

**Problem: Reps aren't using the generated proof packages — adoption is low.**
*Solution:* Reduce friction in the workflow. The package should arrive in the rep's existing tools (Slack, CRM, email) without requiring them to open a separate system. Also reduce length: generate a "Rep Quick View" (3 bullet points + one narrative paragraph) as a separate output alongside the full package. Use win/loss data to show reps which deals used proof packages vs. didn't — make the ROI of adoption visible in their pipeline metrics.
