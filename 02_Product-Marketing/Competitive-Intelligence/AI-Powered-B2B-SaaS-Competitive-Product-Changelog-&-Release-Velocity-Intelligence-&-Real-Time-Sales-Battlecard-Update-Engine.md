## Overview
Continuously monitors competitor product release notes, changelogs, community forums, and review site mentions to measure competitive product velocity, surface quality issues, and auto-update sales battlecards in real time. Use this when you need a living competitive intelligence program — not a quarterly static update — that keeps sales armed the moment a competitor ships something new.

## Integration Tips

- **GitHub (for open-source or dev-tool competitors)**: Watch competitor public repos — commit frequency, branch activity, PR titles, and new file structures reveal feature work before official release. Use GitHub's watch/notification system and parse diffs with AI weekly.
- **Competitors' public changelogs (tools like Changelogfy, Headway, or self-hosted)**: Use RSS feeds from changelog tools and pipe into Zapier/n8n → AI classification → Slack alert. Most SaaS companies publish changelogs at `/changelog` or `/releases`.
- **G2/Capterra/TrustRadius**: Set up Google Alerts for `"[Competitor Name]" site:g2.com` and export new reviews weekly. Use AI to extract feature mentions and sentiment. Clay can automate this at scale.
- **Clay + AI**: Build a Clay table where each row is a competitor release. Columns: Release Type, Threat Level (AI-classified), Battlecard Section Affected, Counter-Content Status. Share with PMM weekly via auto-generated report.
- **Highspot / Seismic / Notion**: Create a "Competitive Intelligence Hub" page that this workflow auto-populates. Tag each battlecard update with the source release and date — gives sales team confidence in the evidence trail.
- **Salesforce / HubSpot**: Log competitive intelligence as a custom activity object on open deals. When a competitor ships a Direct Threat release, auto-notify AEs with open competitive deals and push the updated talking point directly to the deal record.
- **Slack**: Send a weekly #competitive-intel digest using a Zapier/Make automation. Format: "🔴 [Competitor] shipped [Feature] — updated battlecard in [link]. Use this when prospects ask about [X]." Keep it under 200 words so reps actually read it.

## Troubleshooting

**Problem: Competitor doesn't publish a public changelog — no release data available**
Solution: Use a three-source workaround: (1) Monitor their G2/Capterra reviews for feature mentions — reviewers almost always describe new features. (2) Watch their LinkedIn company page and employee posts for release announcements. (3) Track their help documentation via web archive diffs (use Visualping or Distill.io to alert when their docs change). The absence of a public changelog is itself a signal — it often means faster-moving releases without quality gates, which is a selling point for your stability.

**Problem: Threat level assessment is triggering HIGH ALERT too frequently, causing sales team alert fatigue**
Solution: Calibrate the threat threshold by ICP fit. A competitor release only qualifies as HIGH ALERT if it directly affects your TOP 3 win themes AND is relevant to your primary ICP segment. Build a filter: "Does this release affect deals in [Healthcare / Enterprise / $100K+ ACV]?" If no, auto-downgrade to MONITOR regardless of feature significance. Review calibration quarterly with your top 5 AEs.

**Problem: Sales team doesn't trust AI-generated battlecard updates because they seem disconnected from real deals**
Solution: Ground every updated talking point in (a) a specific release note quote and (b) a real customer contrast. Never write "Nexflow's audit logs are unreliable" — instead write "Nexflow's v4.2.1 patch notes state 'Fix: timestamps showing UTC for 12% of enterprise accounts' — our logs have been timezone-correct and court-admissible since day one, as [Customer Name] can confirm." The specificity builds trust. Run a monthly "competitive debrief" call with top reps to validate talking points against real deal feedback before the next cycle.
